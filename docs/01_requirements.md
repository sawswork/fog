# 釣りアプリ 機能要件定義 v0.1

作成: 2026-11-04（Claude Docs 版が原本。差分があればこちらを更新する）

## 1. 目的と前提

釣行中にスマホを操作するのは「釣れた魚の撮影」だけ。その1回で釣果とその瞬間の全条件が残り、蓄積データから「いつ・どこで・何が釣れるか」をアプリが自動で示す。

**大原則**

1. 撮影以外は全自動 — 魚種・サイズ・場所・時刻・環境条件・釣行の開始終了はすべてアプリが取得する。ユーザー入力は撮影のみ。
2. 釣果は自動分析 — 記録と同時に分析結果が更新される。ユーザーは結果を見るだけで、集計操作はしない。
3. 完全ローカル — 自前サーバーなし。外部通信は公開API・公開データの取得のみ。画像判定・分析・学習はすべてオンデバイスで行う。

**前提**

- 利用者は本人のみ。アカウント・ログインなし。App Store には出さない。
- 対象は iPhone 16 Pro（iOS 26 以上）専用。LiDAR と Apple Intelligence を前提にしてよい。ウィジェットからの操作を前提とする。
- 釣り場は全国対応。主対象は函館・漁港のロックフィッシュ（テキサスリグ）だが、魚種・釣法は限定しない。
- 全画面を縦スクロールなしで1画面に収める。タブは「ホーム・ログ・撮影（中央）・図鑑・釣り場」の5つ、設定はホーム右上の歯車。UIイメージは Gemini 生成画像（`docs/ui/`）で固めた。
- 入力なしで成立しないデータは「例外的入力」として明示し、未入力でも記録が成立するようにする（例：撮影時のタックル選択、低確信度時の魚種確定、針ロスト）。
- 全機能をループエンジニアリングで一度に実装する。フェーズ分けはしない。

## 2. 自動取得する環境情報の一覧

iPhone 単体（自前サーバーなし）で取得できる情報は下表の通り。釣行中は定期的に、釣果時はその瞬間の値を必ずスナップショットとして保存する。

| 分類 | 項目 | 取得元 | 取得タイミング | 備考 |
| --- | --- | --- | --- | --- |
| 位置 | 緯度経度、釣り場名、釣り場内の立ち位置 | CoreLocation、MapKit 逆ジオ、登録釣り場との照合 | 釣行中は数分間隔、釣果時 | 未登録地点は釣り場を自動作成 |
| 時刻 | 日時、日の出・日の入、朝夕マズメ（薄明）時刻 | 端末時計＋天文計算（オンデバイス） | 常時 | 通信不要 |
| 気象 | 気温、天気、風向・風速・最大瞬間風速、気圧、湿度、降水量、雲量、視程 | WeatherKit（Apple 公式、端末から直接取得） | 1時間ごと＋釣果時 | 予報は取得できる最長範囲（約10日先）まで取り、グラフと釣れ率予測に使う |
| 気圧（実測） | 端末気圧計の実測値と直近3時間の傾向 | CMAltimeter | 釣行中は連続 | 気象 API より細かい変化を取れる |
| 潮汐 | 潮位、満潮・干潮時刻、潮名（大潮〜長潮・若潮。その日の正午の月齢の整数部で決める）、潮位変化率 | 気象庁「分潮一覧表」の60分潮を気象庁所管の全地点分アプリに同梱し、最寄り地点を自動選択して端末内で推算。分潮表のない地点は年始に気象庁の潮位表テキストを取得して補う | 事前計算 | 全国対応。何日先でも計算でき通信不要 |
| 月 | 月齢、月相（満月・新月）、月の出・月の入 | 天文計算（オンデバイス） | 常時 | 通信不要 |
| 海況 | 波高・周期・向き、うねり、海面水温、海流 | Open-Meteo Marine API（無料・APIキー不要・非商用可）。1時間値で約7日先まで | 釣行前と釣行中 | 格子が粗く漁港内は陸扱いになるため、近傍の海上格子点を指定して取得。CC BY 4.0 のクレジットを設定画面に表示 |
| 季節 | 月、旬、水温の季節推移 | 日付＋蓄積データ | 常時 | 分析用の派生値 |
| 活動 | 滞在時間、歩行距離、歩数 | CoreMotion、HealthKit | 釣行中 | 釣り場内の移動量＝探った範囲 |
| 写真 | 撮影時刻、撮影位置、深度情報 | 写真の EXIF、カメラ | 撮影時 | 釣果記録のトリガー |

**通信圏外のとき**：出発前に釣り場ごとの予報値（気象・潮汐・海況）をキャッシュし、圏外では予報値で記録する。通信復帰後に実況値へ自動で置き換える。

**取得できないもの**：実測水温と実測の波は外部センサーがない限り取れない。公開データの推定値で代替し、将来の拡張候補とする。

## 3. 釣行セッションの自動記録

釣り場に着いたら勝手に釣行が始まり、離れたら勝手に終わる。ボウズ（釣果ゼロ）の釣行も記録し、「釣れなかった条件」を分析に使う。

| 項目 | 仕様 |
| --- | --- |
| 開始検出 | 登録釣り場のジオフェンス内、または海岸線から一定距離内に一定時間滞在したら自動開始。アプリを開かなくてもバックグラウンドで動く |
| 終了検出 | 釣り場から離れて一定時間経過、または車の速度での移動を検出したら自動終了。同日の近接釣り場への移動は「ランガン」として1釣行にまとめる |
| 釣り場の自動登録 | 未登録地点で開始したら釣り場を自動作成。名称は逆ジオコーディング（漁港名・地名）から候補を自動付与 |
| 立ち位置 | 釣り場内の移動を低頻度 GPS で記録し、数十 m メッシュの「ポイント」単位で釣果と紐付ける |
| 環境スナップショット | §2 の項目を30分ごとと釣果時に保存。釣行全体の条件推移が後から追える |
| タックル・リグ | 前回のタックル（スピニング／ベイト）とリグ（シンカー重さ・フック・ワーム）を自動で引き継ぐ。変更はウィジェットから1タップ（例外的入力） |
| 針ロスト・追加 | ウィジェットから1タップで記録（例外的入力）。位置と時刻は自動で付く。根掛かりマップの元データになる |
| キャスト数の推定 | Apple Watch 装着時は加速度センサーからキャスト動作を推定し「何投で釣れたか」を出す（将来拡張） |
| 釣行後の確定 | 終了検出後に釣行レポートを自動生成し通知（§5）。誤検出の釣行は通知から破棄できる |

## 4. 釣果記録（撮影だけ）

魚を撮る。それだけで魚種・サイズ・場所・時刻・環境条件・タックルが1尾の記録として残る。

| 項目 | 仕様 |
| --- | --- |
| 撮影の入口 | アプリ内カメラ、ウィジェット、ロック画面のカメラコントロールの3系統。標準カメラで撮った写真も、釣行中の時刻・位置に一致すればフォトライブラリから自動取り込み |
| 魚種判定 | オンデバイスの画像分類（Core ML）。北海道の根魚を優先：アイナメ、クロソイ、マゾイ、シマゾイ、エゾメバル（ガヤ）、ハチガラ、カジカ、ホッケ、クジメ、ソイ類の近縁種。確信度を保存する |
| 低確信度のとき | 候補3種を表示し1タップで確定（例外的入力）。放置しても最有力候補で記録は成立する |
| サイズ推定 | 魚だけを写し、LiDAR の深度情報から全長を推定する（基準物は写さない）。LiDAR 深度のない写真（標準カメラからの取り込みなど）はサイズ未計測として記録する。推定幅（±cm）を保存し、自己記録の判定には推定幅を考慮する |
| 環境の紐付け | 撮影時刻から直近のスナップショットを補間して付与。潮と月はその時刻で再計算 |
| 場所・タックルの紐付け | セッション、ポイント（立ち位置）、その時点で有効なタックル・リグを自動で付与。撮影画面でタックル（スピニング／ベイト）とリグを1タップで切り替えられる（例外的入力） |
| 同一個体のまとめ | 数分以内の連続撮影で同じ魚種・近いサイズの写真は1尾にまとめ、ベストショットを自動選択 |
| 記録の自動判定 | 初めての魚種、魚種別自己記録、釣り場別記録を記録時に判定し通知。図鑑へ自動登録 |
| 後からの修正 | 魚種・サイズの誤判定は後で修正でき、修正内容は端末内の判定モデルの補正に使う |
| リリース／キープ | 自動判定できないため既定はリリース。後から変更可（将来拡張） |

## 5. 自動分析

分析はすべて端末内で、記録のたびに自動更新される。

**釣れ率スコア（0〜100）**

- 現在地（または選んだ釣り場）×現在時刻の条件に対して算出する。先の推移はデータが取れる範囲まですべて出し（潮・月・日の出入りは無期限、気象は予報の最長範囲）、ピーク時間帯を示す。72時間などの固定上限は設けない。
- 構成要素：時間帯（マズメ・夜）、潮（潮名・上げ下げ・潮位変化率）、気圧傾向、風（向き・強さ）、波、水温・季節、月相、その釣り場での自分の実績。
- データが少ないうちは一般的な釣りの知見（ルールベース）で算出し、釣行が蓄積されるほど自分のデータの重みを上げる。ボウズの釣行も学習に使う。
- 内訳（どの要素がスコアを上げ・下げているか）を必要なときだけ見られる。
- 魚種別スコアも出す。

**統計と相関**

| 分析 | 内容 |
| --- | --- |
| 釣り場別 | 釣行数、釣果数、釣行1時間あたり釣果数、ボウズ率、釣れたポイントのヒートマップ、針ロスト率（根掛かりマップ） |
| 魚種別 | 釣れた条件の分布（潮位・潮の時間・水温・風・気圧傾向・時間帯・月）、サイズ分布、最大サイズの推移 |
| 時間帯別・月別 | 釣果数と平均サイズを時間帯×月で集計。シーズンの立ち上がりと終わりを示す |
| タックル・リグ別 | シンカー重さ・ワーム・フックごとの釣果とロスト |
| 前回比・傾向 | 同じ釣り場の前回との条件差と結果差。月ごとの釣果推移 |

**図鑑の自動更新**

- 魚種ごとに最大サイズ、初釣果日、尾数、釣れた釣り場、釣れやすい条件（分析から自動生成）を持つ。
- 図鑑は自分が釣った魚種だけで構成し、初釣果で自動追加される。未釣果のシルエット一覧は作らない。

**釣行後レポート（自動生成・通知）**

- 終了検出と同時に生成：釣果サマリー、条件の推移、釣れた時間帯と潮の関係、前回比、次回への一言。
- 文章生成はオンデバイス（Apple Intelligence の Foundation Models）を使う。

## 6. データ管理

| 項目 | 仕様 |
| --- | --- |
| 保存先 | 端末内 DB（SwiftData）。写真はフォトライブラリを参照し、アプリ内にはサムネイルと判定結果だけ持つ |
| バックアップ | iCloud（CloudKit プライベート DB）へ自動同期。機種変更でも引き継げる |
| エクスポート | 釣果・釣行・環境スナップショットを CSV／JSON で書き出し。写真付き ZIP も可 |
| インポート | エクスポートした JSON の復元。他アプリからの取り込みは対象外 |
| 外部通信 | WeatherKit、Open-Meteo Marine、気象庁潮位表、登録した RSS の取得のみ。位置情報は取得クエリに必要な精度に丸めて送る。写真と釣果データは一切送信しない |
| 判定モデル | 魚種判定モデルはアプリに同梱。ユーザーの修正による補正は端末内に保存し、モデル更新はアプリ更新で配布 |
| 削除 | 釣果・釣行・釣り場の個別削除と全データ削除。削除は分析に即時反映 |

## 7. 非機能要件

| 項目 | 目標 |
| --- | --- |
| バッテリー | 10時間の釣行でアプリの消費 20% 以下。GPS は滞在中は低頻度、移動検知時だけ高頻度。環境取得は1時間間隔 |
| オフライン | 圏外でも開始・終了検出・撮影・魚種判定・釣れ率算出が動く。潮・月・日の出入りは通信不要 |
| 魚種判定精度 | 主対象魚種で正解率 90% 以上。判定は2秒以内。確信度 70% 未満は候補表示へ |
| サイズ推定精度 | LiDAR で ±2cm を目安。推定幅を必ず表示 |
| 自動開始の誤検出 | 釣り場近くを通過しただけでは開始しない。誤検出はレポート通知から1タップで破棄 |
| 応答性 | ウィジェットの釣れ率更新は15分間隔。アプリ起動から撮影可能まで1秒以内 |
| 対応環境 | iPhone 16 Pro（iOS 26 以上）専用。本人利用のみで App Store には出さない |
| 権限 | 位置情報（常に許可）、カメラ、写真ライブラリ、モーション、通知。初回起動時に理由を示してまとめて取得 |
| 開発制約 | Mac なし（GitHub＋CI でビルド、iPad で作業）。ループエンジニアリングで一貫して作成 |

## 9. 決定事項・要調査・次ステップ

2026-11-04 に未決事項をすべて判断した。

| 判断事項 | 決定 |
| --- | --- |
| タブ構成 | ホーム・ログ・撮影（中央）・図鑑・釣り場の5つ。設定はホーム右上の歯車 |
| サイズ推定 | 魚だけを写して LiDAR で推定。基準物は使わない。iPhone 16 Pro 専用でリリースしない |
| 画面構成 | 縦スクロールなし、全画面を1画面に収める（図鑑グリッドのみ縦スクロール可）。UIイメージは Gemini 生成画像で固める |
| 例外的入力 | 撮影時のタックル選択を追加。針ロストは残すが優先度は下げる |
| 対象範囲 | 全国対応。ネット上の釣果情報も可能なら収集する（F-27、COULD） |
| 実装方針 | フェーズ分けせず、ループエンジニアリングで全機能を一度に実装 |
| 先の表示範囲 | 72時間の固定上限は設けず、データが取れる範囲まですべて表示 |
| ホームの主役 | 釣れ率の大きな数字を主役にし、潮グラフは下に横スクロールで置く |
| 図鑑の範囲 | 自分が釣った魚種だけ。未釣果のシルエット一覧は作らない |
